# BilimUz Coding Standards

## Purpose

This document defines the coding standards for the BilimUz project.

Every developer and every AI assistant must follow these rules.

---

# General Principles

Always follow

Clean Architecture

SOLID

DRY

KISS

YAGNI

Repository Pattern

Service Layer

Dependency Injection

Never write spaghetti code.

---

# Code Quality

Write readable code.

Write maintainable code.

Write scalable code.

Write reusable code.

Avoid duplicated logic.

Avoid unnecessary complexity.

---

# File Size

Maximum file length

300 lines

If exceeded,

split into multiple files.

---

# Function Size

Maximum

40 lines

Large functions must be refactored.

---

# Comments

Explain WHY.

Avoid explaining WHAT.

The code should explain itself.

---

# Error Handling

Never ignore exceptions.

Always return meaningful errors.

Never expose internal implementation.

---

# Logging

Log

Errors

Warnings

Critical Events

Security Events

Never log passwords.

Never log tokens.

---

# Documentation

Every module must include

README

Examples

Architecture

Future Improvements

---

# Production Rule

Never generate demo code.

Never generate placeholder implementations.

Always generate production-ready code.
